# ebook-maker フェーズ1 設計 (画像調整 + PDF/EPUB変換)

## 概要

ユーザーが持つ文書のスキャン画像を輝度調整・画質最適化し、1つのPDFまたはEPUBに変換するWebアプリ。著作権保護の観点から、画像は一切サーバーに送信せず、すべてブラウザ内(クライアントサイド)で処理する。

OCR機能(NDLOCR等を使ったテキスト認識)は将来のフェーズ2として別設計とする。本設計はフェーズ1(画像処理・変換)のみを対象とする。

## 要件サマリ

- 入力: 複数画像ファイルの一括選択、またはフォルダ選択。ドラッグ&ドロップ対応
- 想定規模: 1冊あたり数十〜200ページ程度
- 画像処理: 自動輝度・コントラスト補正 + 手動スライダ調整(プレビュー付き)
- 見開き結合: オプション機能。ユーザーが手動でページを選択し、2ページを1枚に結合。プレビュー付きUI
- ページ編集: 並べ替え(ドラッグ)、削除、タイトル等メタデータ入力
- 出力: PDF / EPUB(固定レイアウト、画像埋め込み型) をユーザーが選択
- サーバー送信なし。全処理をクライアント(ブラウザ)内で完結

## 技術スタック

- React + TypeScript + Vite
- 画像処理: Canvas 2D API
- PDF生成: `pdf-lib`
- EPUB生成: `JSZip` による手組み(固定レイアウト・画像埋め込み型EPUB)
- 状態永続化: IndexedDB(ページ画像・調整パラメータ、リロード耐性)
- ホスティング: GitHub Pages(静的配信)

## 検討した処理方式(採用: A案)

- **A案(採用)**: Canvas 2D APIでプレビュー・調整をメインスレッド処理。書き出し(PDF/EPUB生成)のみWeb Workerに逃がしUIブロックを回避。実装がシンプルで200ページ規模に十分対応可能。
- B案(WebAssembly画像処理): 高速化見込めるが200ページ規模ではCanvas 2Dと体感差がなく、ビルド複雑化のみでオーバースペックのため不採用。
- C案(OffscreenCanvas+複数Worker並列処理): UI応答性は最高だが実装複雑で今回の規模には過剰のため不採用。

## アーキテクチャ概要

完全クライアント処理(サーバーなし静的サイト)。

```
[画像取込] → [ページ一覧(並べ替え/削除/見開き結合)] → [輝度調整(自動+手動プレビュー)] → [メタデータ入力] → [書き出し(PDF/EPUB選択)]
```

- 画像は一切サーバー送信せずブラウザメモリ/IndexedDBのみで完結
- 書き出し処理(PDF/EPUB生成)のみWeb Workerへ逃がしUIブロック回避
- 状態管理: React state + IndexedDB

## コンポーネント詳細

- **ImportPanel** — ファイル/フォルダ選択、ドラッグ&ドロップ受付。画像デコードしIndexedDBへ格納
- **PageList** — サムネイル一覧。ドラッグ並べ替え、削除、見開き結合トグル(2ページ選択→結合プレビュー→確定)
- **AdjustmentEditor** — 選択ページのCanvasプレビュー。自動補正(ヒストグラム平坦化/コントラスト自動)をデフォルト適用し、明るさ・コントラストスライダで上書き可能。他ページへの一括適用ボタンも用意
- **MetadataForm** — タイトル・著者入力
- **ExportPanel** — PDF/EPUB選択、書き出し実行(Web Worker起動)、進捗表示、完了後ダウンロードリンク生成
- **ImageStore**(非UI) — IndexedDBラッパー。元画像Blob + 調整パラメータ + ページ順を保持
- **ExportWorker**(非UI) — pdf-lib/JSZipによる生成処理を担当

見開き結合は独立ステップ。結合後は1ページ画像として以降のリスト・調整対象になる。

## データフロー

1. **取込**: ファイル/フォルダ選択 → 各画像デコード → `ImageStore`(IndexedDB)へ原本Blobとして保存、ページエントリ生成(id, 順序, 原本参照, 調整パラメータ初期値)
2. **一覧操作**: `PageList`はIndexedDBのページエントリをReact stateにミラー。並べ替え/削除はstate更新→IndexedDB反映(デバウンス書き込み)
3. **見開き結合**: 2ページ選択→Canvas上で横結合し新規画像生成→元2ページを1エントリに置換(結合前画像は破棄、UNDOはページ削除操作の取消のみ対応)
4. **輝度調整**: `AdjustmentEditor`でページ選択→原本BlobをCanvasにロード→自動補正関数適用→スライダ操作でパラメータ再計算→プレビュー即時反映。確定時は「パラメータのみ」をIndexedDBに保存(原本は非破壊、都度再描画)
5. **メタデータ入力**: タイトル・著者をReact stateに保持、書き出し時にPDF/EPUBメタデータへ渡す
6. **書き出し**: ExportPanelがページ順に「原本+パラメータ」をWorkerへ転送(Transferable/構造化複製) → Worker内でCanvas再描画→補正済みビットマップ生成→pdf-lib(PDF)またはJSZip(EPUB)で組み立て→完成Blobをメインスレッドへ返却→ダウンロードリンク生成

非破壊設計(原本+パラメータ保持)により、調整のやり直しや見開き結合前の状態確認が可能。

## エラーハンドリング

- **非対応ファイル形式**: 画像デコード失敗時は該当ファイルをスキップし、一覧上に「読込失敗」バッジ表示。他ファイルの取込は継続
- **メモリ/容量不足**: IndexedDB書き込み失敗(`QuotaExceededError`)時はエラーダイアログ表示し、取込・処理を中断。ページ削除で容量確保を促す
- **書き出し失敗**: Worker内例外はメインスレッドへメッセージ返却しExportPanelにエラー表示、部分生成物は破棄。リトライボタン提供
- **ブラウザ非対応**: Web Worker / IndexedDB 非対応環境では起動時に警告表示(対象は最新Chromium/Firefox/Safariのみ想定、古いブラウザは非対応表明)
- **大量ページ時の警告**: 200ページ超で取込時に「処理が重くなる可能性」の非ブロッキング警告を表示(処理自体は継続可能)

## テスト方針

- **単体テスト**(Vitest): 輝度自動補正関数、見開き結合の画像合成ロジック、PDF/EPUB組み立てロジック(pdf-lib呼び出し部・EPUB XML生成部)を純粋関数として切り出しテスト
- **コンポーネントテスト**(React Testing Library): PageListの並べ替え/削除操作、AdjustmentEditorのスライダ→プレビュー反映
- **Workerテスト**: ExportWorkerのメッセージハンドラを直接呼び出し、入力(ページ配列)→出力(Blob)の検証。小規模フィクスチャ画像使用
- **結合テスト**: 取込→調整→見開き結合→書き出しの一連フローをE2E(Playwright)で1シナリオ実施。生成PDF/EPUBはファイルサイズ・ページ数のみ検証(内容ピクセル比較は行わない)
- **手動確認**: 実際のスキャン画像サンプルで見た目品質(輝度調整結果)を目視確認。自動テストでは主観品質は担保しない
