# OCR (フェーズ2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** NDLOCR-Lite の ONNX モデルをブラウザ内(Web Worker + onnxruntime-web)で動かし、各ページのOCR結果を確認・修正できる新しい工程(step)を追加する。

**Architecture:** OCRは「レイアウト検出(DEIMv2)→ 行ごとに文字認識(PARSeq, 行の文字数カテゴリで3モデルを使い分け)→ 読み順ソート」の3段。画素処理・後処理はすべて `RawImage` を受け取る純関数(`src/lib/ocr/`)として書き、jsdomでTDDする。推論はWorker内の `onnxruntime-web` (WASM, 単一スレッド) で行い、モデルは初回だけ取得して Cache API に保存する。結果はIndexedDBの新しいストア `ocr`(ページIDキー)に保存し、UIは既存の wizard に工程3「OCR確認・修正」を追加する。

**Tech Stack:** onnxruntime-web (WASM/CPU), React 19, Vitest (jsdom), Playwright, IndexedDB (既存 `ImageStore` を v2 に拡張)

**Spec:** 未作成。参照元: https://github.com/yuta1984/ndlocrlite-web (実装の下敷き) / NDLOCR-Lite (モデル本家)。既存: `docs/superpowers/specs/2026-09-05-ebook-maker-phase1-design.md`

## Global Constraints

- 画像・OCR結果は一切サーバーへ送信しない(フェーズ1の原則。モデルの静的ファイル取得のみ通信可)。
- ホスティングは GitHub Pages(`base: '/ebook-maker/'`)。**COOP/COEP ヘッダを付けられない**ため `ort.env.wasm.numThreads = 1`、`ort.env.wasm.proxy = false`、`executionProviders: ['wasm']` 固定(SharedArrayBuffer に依存しない)。
- OCR対象は無加工の原本Blob(`PageEntry.blobId`)。明るさ/コントラスト調整はOCR入力に反映しない。
- 既存工程の番号が1つずつずれる(工程3が「詳細＆書き出し」になる)。`window.EbookMaker` の `goToStep` / `describe` / e2e を必ず追従させる。
- UI文言は日本語、コード内コメントも既存に合わせて日本語。lint は `oxlint`、型検査は `npm run typecheck`。
- スコープ外(別計画): OCRテキストのPDF透明テキスト層・EPUB本文への埋め込み。データモデルはこれを妨げない形にする。

- [ ] **Step 3: 実装**

```ts
import type { Detection } from './types'

// 行の縦横比の中央値で縦書き/横書きを判定し、その向きの読み順に並べる。
export function sortReadingOrder(dets: Detection[]): Detection[] {
  if (dets.length === 0) return []
  const tall = dets.filter((b) => b.h > b.w).length > dets.length / 2
  const cx = (b: Detection) => b.x + b.w / 2
  const cy = (b: Detection) => b.y + b.h / 2
  return dets.slice().sort((a, b) =>
    tall
      ? cx(b) - cx(a) || a.y - b.y // 右→左、同列は上→下
      : cy(a) - cy(b) || a.x - b.x, // 上→下、同行は左→右
  )
}
```

(実物のスキャンで列/行の中心が微妙にずれる場合に備え、`Math.abs(cx(a)-cx(b)) < 幅の半分` なら同列とみなして `y` で比較する形に強化するテストを追加してから直す。)

- [ ] **Step 5:** 同じ流れで残りを1ファイルずつ(テスト→FAIL→実装→PASS)。各テストの中身:
